# 巨人投掷机制重构实施记录

> 执行方式：按 writing-plans / executing-plans 流程组织实现，独立审查几何与房屋检测。

**目标：** 保留动画释放、弧线节奏、半血一次投掷、升阶下砸与三连投，让冒险地图统一使用实际几何选点。

**架构：** BoardLandingGeometry 只提供释放时的可选横向区间；ImpThrowPlanner 把投掷意图变为整组 ImpThrowPlan 值对象；小鬼按累计动作时间采样，MoveComponent 负责唯一的脚点位移；MainGameHome 自行延后临时飞行者的失败判定。

**技术栈：** 现有 Godot 4 / GDScript、BoardRuntime、ZombieManager 和动作因子体系，不新增依赖或全局管理器。

**设计依据：** 本次讨论确认的投掷分层方案及 2026-11-19 用户要求：几乎没有普通关卡，统一冒险地图几何，严格控制架构和 bug。

4. 同组共享随机中心，所有散布点分别约束；飞行末帧精确截断。
