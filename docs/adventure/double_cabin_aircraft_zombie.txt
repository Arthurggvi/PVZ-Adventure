阶段：原版数据和拆包索引已核对；完整动作包未取得；本轮仅写工程文档，不注册、不实装、不运行测试。

一、物种身份与原版规则
- 身份：中国版 PVZ2 天空之城 Double-Cabin Aircraft Zombie（双舱飞机僵尸）。
- 游戏内部名称：skycity_twinsplane；2015 年实物拆包讨论记载资源组 21477000（其十六进制／索引格式未验证）。
- 原版首次出场：Sky City Day 6 困难模式；普通关第 7 天正式引入。
- 生命：1200，总计两舱各 600；机舱独立受击和死亡资格，不是统一 1200 血条。
- 位移：每 3 秒前进一格；占两条相邻攻击行，整体物理占位近似 2×2 格。
- 伤害：撞击沿途植物为每秒 1000（用户截图“碾压”）；撞上玩家飞船造成 800 伤害。
- 若仅一个机舱血量归零，另一舱仍然能够推进；两个均归零才判整机被击毁。
- 飞机靠近戴夫号甲板后无返航，会直接撞击舰体并结束本体；不混入之前战斗机的返航原逻辑。
- 植物攻击：两条行都能分别攻击相应机舱，命中必须对齐实际行与当前机舱。
- 寒冷：冰封状态转为减速，保留真正伤害，不自行增加全控免疫。
- 原版不被归为可被三叶草直接吹走的“飞行僵尸”；天空之城原关禁止三叶草。
- 本项目用户规则覆盖原版：必须能被三叶草吹走，含单舱已毁、双舱未毁及正常推进态。

四、建议的数据与生命周期结构
一架飞机对应一名 Zombie000Base 战场敌人；单一波次预算、唯一死亡与清场登记，
不能为了每舱受击在 ZombieManager 中注册两只完整僵尸。
一个 PlaneMotion 负责统一世界脚点/横向位移，始终保持两舱相对距离固定；
两个 CabinHitbox 分别属于两条相邻逻辑行（upper/lower），每舱单独持有当前 0–600 HP。
受击路由按攻击行确定 cabin_id，跨两行范围伤害每舱最多结算一次，不叠计一发子弹；
若玩家攻击实际覆盖两个区域，可根据原版命中规则对两舱各结算一次。
生命值扣到零的机舱永久记 disabled，不接受负血；保留机体继续飞行直到另一舱也失去生命。
不要创建单侧死亡立即 queue_free 的破机体；只有两舱都 disabled 才触发一次整体死亡，
或者完整机体到达甲板按原版冲撞一次退场。
损坏美术与检测框必须随 cabin 状态同时改变：是否仍能在该行撞击以及残存机翼表现，
等拿到真实分段动画后再确认原作细节，不用猜测单舱拆除后的碰撞宽度。
原游戏贴近舰体时按 800 伤害调用“舰体耐久”机制；本工程若当前战场没有舰体血池，
优先复用一次 zombie_go_home 失败事件，不凭空添加一个不可见的飞船血条。
撞击与击毁两个原因不可重入；若同一帧两舱死光且处于冲撞区，只提交一个最终结果。
三叶草吹离需优先于继续碾压/撞船的待执行回调：is_blover_flying_target() 为 true，
handle_blover_wind() 接管统一飞机；一次吹离停止两舱的攻击与推进并走
retire_from_battle()，不产生每舱分别被吹、双倍波次减员或额外爆炸。
普通子弹和地面植物仍能针对其所在行命中机体；“三叶草视为飞行目标”和
“真实受击类别”必须是两个不同的查询，不把 IsSky 当成唯一统一标志。
如果原版空中机舱场景有特殊高度判定，保持逻辑脚点与展示离地量分离。
两舱整体最少需要两条相邻有效行；单行关卡拒绝刷出。不得跨越关闭的行、
稀疏棋盘的有效种植位边界或将两个不同平台的 hitbox 锁死到初始世界 Y。
冻结则统一在机体动作速率上施加“冰封→减速”，不各舱分别叠加双倍减速。
状态：SPAWNING → ADVANCING (both / only upper / only lower) →
CRASHING 或 DYING 或 BLOVER_EXIT；终态不能再次切换成移动中。

五、质量门槛
1. 获取正式原作资源，保存原件哈希与来源；源帧完整性核验在写代码之前。
2. 原作确切动作：双螺旋桨、两名驾驶员、正常推进、单侧破损、坠毁、舰体撞击；
   若某个动作缺失，显式标记缺失，不用整张 PNG 以正弦位移冒充完整原版动画。
3. 音效必须按真实事件绑定，来源未核实者标记“临时替代”，绝不直接套用别的僵尸声音。
4. 工程实机验收：两行受弹→左舱先归零→右舱持续→另一舱归零且只死一次；
   右舱先死对照、两舱同帧死亡、冰冻减速与其他状态互斥。
5. 验证三叶草对完整、单舱残存机体均可吹离；重复吹风不残留区域，
   一架飞机在波次计数中只消失一次。
6. 正式甲板撞船、普通草坪/关卡进家失败、移动平台和高低差双行几何，
   路径只读取真实 board，且不会触发多次失败。
7. 根据 AGENTS.md 默认不新增或运行测试；本轮只是文档归档，没有实装或实机验收。
8. 未来资产目录受 .gitignore 排除，正式资源必须定向 git add -f；
   禁止 git add .、自动 push、覆盖正在并行编辑的文件。
