# Buff 图鉴

## 用途与入口

冒险图鉴的第四个分类「Buff」集中展示增益、减益、控制和特殊战斗状态。
条目直接开放查阅，不读取或写入物种发现记录；搜索范围包括名称、分类、说明与来源。
右侧详情左半区为手动滚动的效果说明，右半区为对应演示及重播、停止按钮。
同名效果由多种技能施加时，通用规则和来源参数分开说明。

## 数据权威与职责

- 实际结算始终由原战斗组件负责。图鉴目录仅保存只读说明、分类、来源和演示参数。
- 负面效果首先对照 `scripts/adventure/adventure_plant_negative_effects.gd` 的完整 Kind 枚举，再检查原生控制和其余共享状态组件。
- 持续伤害、冻结值、引爆值、缠怨等条目须核对对应 `scripts/adventure/adventure_*_effect.gd`。
- 防护规则核对 `scripts/character/components/damage_*_effect.gd`；强化规则核对转职组件、僵尸临时增益与角色技能。
- 单个技能的完整技能介绍仍属于原有技能／物种页面；Buff 页说明它施加的共享状态。
- 修改任何状态规则时，必须同步检查本目录说明及演示参数。不能仅根据旧文案或技能名称推断效果。

## 接口

`scripts/adventure/ui/buff_almanac_data.gd` 为目录唯一入口：

- `rows(search: String = "") -> Array[Dictionary]` 返回过滤后的只读目录行。
- `entry(buff_id: StringName) -> Dictionary` 按稳定语义 ID 读取详情。
- `profile(type_id: int) -> Dictionary` 适配图鉴宿主的整数选择协议。
- `type_id` 是完整目录中的索引加一，0 为空；过滤前后不改变同一条目的编号，绝不写入存档。
- 每条包含 `buff_id`、`title`、`category`、`color`、`symbol`、`summary`、`stats`、`effects`、`sources`、`preview_id` 和演示参数。
- `effects` 由 `title/options` 分组，保留刷新、叠加、免疫和例外的独立阅读顺序。
- `sources` 使用玩家能理解的植物、敌人或技能名称；源码路径放在注释中。

`scripts/adventure/ui/buff_almanac_detail.gd` 仅负责标题、分类、正文排版、舞台与控制按钮。
公开属性 `type_id` 由宿主在入树前赋值。详情关闭时立即调用舞台 `stop()`。

`scripts/adventure/ui/buff_almanac_preview.gd` 提供：

- `required_resource_paths(entry: Dictionary) -> PackedStringArray`：仅声明该条目需要的资源。
- `show_buff(entry: Dictionary)`：建立当前条目的独立演示。
- `replay()`：重新开始当前效果，保留正文的阅读位置。
- `stop()`：停止本页视觉和时钟，允许再次重播。

## 演示边界

- 使用 420×330 的独立 SubViewport，禁止向正式战斗场景注册实体、碰撞、伤害和状态。
- 角色骨架只保留展示需要的纯视觉部件；动画只允许指向展示节点的属性轨道，不能复制方法回调或战斗轨道。
- 优先复用已有纯视觉素材；直接依赖战斗宿主的效果不能通过伪造战斗身份执行。
- 各状态应展示可辨认的行为差别：移动／动作速度、停止动作、转向、受击／护甲、层数、持续掉血等。
- 舞台使用便于观察的示例强度与时间，界面明确标注；实际规则以左侧说明为准。
- 停止、重播、切换和关闭都只影响本详情页。禁止改变 Engine.time_scale、Global 战斗字段、资源原件或玩家存档。

## 资源与生命周期

继续由现有图鉴宿主和共享 ResourceBatch 进行按需资源准备。
目录符号不加载角色场景；只有当前选中的状态请求其演示依赖。
切换分类／搜索／条目时旧请求作废；完成后再次核对目录版本与选择身份。
关闭不等待后台读盘，未完成的批次交给现有 AdventureToolbar 回收。
此功能不增加 Autoload，不改变 Bootstrap 或正式场景切换协议。

## 后续新增状态

1. 先确认状态的真实作用、施加对象、强度、时间、叠加、刷新、免疫和清除方式。
2. 在对应类别的数据文件添加一条稳定语义 ID，来源注明实际入口。
3. 为预览配置恰当的样本和行为；新增视觉资源必须加入该条目的资源声明。
4. 若既有演示模式无法表达差异，扩展对应的小型表现模块，不能在图鉴中实现第二套战斗规则。
5. 同步更新下面的覆盖清单，并检查分类、搜索、空结果与关闭期间的旧任务清理。

## 核验记录

- 独立代码审查确认41条均有具体演示分支，统一负面入口的16种状态均被覆盖。
- Godot 4.7.2 的工程级 `--headless --editor --import` 导入与脚本扫描退出0，未出现 ERROR / SCRIPT ERROR。
- 独立脚本 `--check-only` 无法建立工程 Autoload 的 Global 上下文；采用工程级扫描核验，没有为此改动单例结构。
- 本轮遵守仓库「默认不新增、不运行测试」约定，未运行测试套件、战斗场景或图形／Android真机验收。
- 导入扫描、接口核对与代码审查不能替代实际游戏中的布局、动画和操作验收。
