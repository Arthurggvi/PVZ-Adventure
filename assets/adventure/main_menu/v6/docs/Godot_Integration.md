# Codex 施工说明——PVZ Adventure MainMenu v6 美术集成

**范围：美术装配，禁止改动存档语义；旧“开始/继续”入口可能存在缺陷，未经审计不要直接连接至 `start_new()`。**

## 1. 先审现有文件

定位当前 Godot 主菜单场景、`UserManager`/`SaveService` 与冒险入口代码、Godot 的主场景尺寸。不要推倒重写原有主菜单/玩家选择系统；只替换视觉结构。没有本机源码前，任务书不对实际类名、信号名或场景路径作不实假设。

## 2. 资源图层（自底向上）

1. `background/coastal_yard.png` 作为铺满1920×1080逻辑画布的背景。
2. `overlays/contact_shadows.png` 位于四个主体**下方**。
3. 四个独立 `subjects/*.png`；它们的 `rect` 用 `layout.json` 精确定位。
4. `overlays/dock_foreground.png` 绘制在四主体前，以码头木板遮挡船；该覆盖层像素来自同一背景画面，因此不得被独立移动或缩放到与背景不同的倍率。
5. `overlays/ship_waterline_ripples.png` 是可选静态叠加；动态水纹建议由 Shader / Particles 实现，不需要更换底图。
6. 四个 `buttons/*_blank.png`。同一路径下的 `states/` 提供可选的 hover/pressed/disabled 图。
7. 将四个标题放在**独立的 Godot `Label`**，不要烘焙进木牌。示例文字层 `overlays/example_runtime_text_only.png` 仅供对照，正式主菜单不要加载此文件。
8. 最上层保留原版玩家档案、设置/帮助/退出等既有 UI。

## 3. 交互语义

- `即刻启航`：**仅一个入口**，读取原版当前玩家关联的冒险存档；由 `intro_completed` 等状态决定戴夫引导。无存档才初始化，有进度恢复。不得由普通入口删除/重建当前档案。
- `家园`、`研究棚`、`补给车`：遵守尚未实装的功能状态，可以做禁用/提示，**不得自行发明新玩法**。
- 允许对四个主体加入 `mouse_filter = IGNORE`，由木牌所在的独立交互区域处理点击；或使用透明的 Click Area 与牌面同矩形。
- 菜单逻辑与美术节点分层；优先 `.tscn` 独立编辑 UI，不要运行时大量 `Control.new()`/硬编码所有逻辑。

## 4. 显示与布局

`layout.json` 用 **1920×1080** 逻辑坐标。目标分辨率：1920×1080、1280×720、1066×600。务必保持等比适配（1066×600 与16:9略有小偏差）；避免任意拉伸导致圆形、字体与建筑变形。

注意所有 `rect` 为素材的画布包围矩形，内部仍有透明边缘；实际可点击区域可采用近似木牌实心区域收缩边距，保证不误触相邻主体。

## 5. 验收清单

1. Godot 导入无缺图、透明背景没有黑底/棋盘格。
2. 四个入口在3个指定分辨率都可辨、中文文本未被截断。
3. 码头前缘遮住船的靠岸部分，水纹不压到木板上；随窗口缩放不发生遮挡错位。
4. 原生玩家档案选择与设置/帮助/退出可用。
5. 从两个不同玩家档案分别进入不串档；已有冒险档案不可被“即刻启航”覆盖。
6. 鼠标悬停/按下/禁用态只调整独立按钮，不拖着背景一起动。
7. 真正完成实机 UI 测试和入口存档测试后，才能称 Godot 集成验收通过。
